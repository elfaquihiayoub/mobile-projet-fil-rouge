Examples:


# 7. SEPARATE OBJECT REPRESENTATION FROM DATA ACCESS

Where appropriate, distinguish between:

### Entity / Object

Represents one object.

Example:

```php
$livre = new Livre(...);
```

and:

### Repository / Data access

Responsible for retrieving and persisting objects.

For example:

```php
$repository->getAll();
$repository->find($id);
$repository->create($livre);
$repository->update($livre);
$repository->delete($id);
```

Do not introduce Repository classes everywhere if the existing MVC implementation already provides an equivalent clean responsibility.

Use this pattern where it actually helps demonstrate the lesson.

# 8. API

Introduce a clear PHP API layer for the management interfaces that will be converted to Fetch/AJAX.

The API must return JSON.

Example:

```text
GET    /api/adherents
POST   /api/adherents
PUT    /api/adherents/{id}
DELETE /api/adherents/{id}
```

Equivalent routing is acceptable if the current PHP project uses another routing mechanism.

The exact URL structure is less important than having a clear HTTP API.

---

# 9. HTTP METHODS

Use HTTP methods according to their purpose.

### GET

Retrieve data.

Example:

```text
GET /api/rayons
```

Returns the list of rayons.

### POST

Create a new resource.

Example:

```text
POST /api/rayons
```

Request body:

```json
{
    "nom": "...",
    "description": "..."
}
```

### PUT

Update an existing resource.

Example:

```text
PUT /api/rayons/3
```

### DELETE

Delete an existing resource.

Example:

```text
DELETE /api/rayons/3
```

Do not simulate every operation with GET or POST if the current lesson specifically requires understanding these HTTP methods.

---

# 10. API RESPONSE FORMAT

Return valid JSON from API endpoints.

Example:

```json
[
    {
        "id": 1,
        "nom": "Informatique",
        "description": "..."
    }
]
```

or, where a structured response is useful:

```json
{
    "success": true,
    "data": [...]
}
```

The format should remain consistent throughout the API.

Never return HTML/PHP warnings from an API endpoint.

Handle errors as JSON responses.

---

# 11. JAVASCRIPT FETCH

Replace unnecessary traditional form submissions on the adapted management interfaces with Fetch.

Example:

```javascript
fetch(API_URL)
    .then(response => response.json())
    .then(data => {
        // update DOM
    });
```

Use:

```javascript
method: "POST"
```

for creation,

```javascript
method: "PUT"
```

for modification,

and:

```javascript
method: "DELETE"
```

for deletion.

Send JSON when appropriate:

```javascript
headers: {
    "Content-Type": "application/json"
},
body: JSON.stringify(data)
```

---

# 12. DOM MANIPULATION

The frontend should dynamically update the interface.

For example:

```javascript
const tableBody = document.getElementById("table-body");
```

Then:

```javascript
tableBody.innerHTML = "";
```

and dynamically generate rows from API data.

Do not reload the entire page after every operation when Fetch can update the current interface.

After creating a record:

```text
POST
 ↓
API
 ↓
success
 ↓
reload data with GET
 ↓
update table
```

The same principle applies to update and delete.

---

# 13. DOM EVENTS

Use event listeners for interface interactions.

Examples:

```javascript
form.addEventListener("submit", ...)
```

```javascript
button.addEventListener("click", ...)
```

```javascript
document.addEventListener("DOMContentLoaded", ...)
```

Avoid inline JavaScript such as:

```html
<button onclick="...">
```

when an event listener provides a cleaner implementation.
